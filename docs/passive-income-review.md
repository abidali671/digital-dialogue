## 1. Niche — what to write about

### Recommended niche

**Full-stack freelancing with MERN / Next.js**

Help developers who know some React/Node and want to:

- get freelance clients
- price and deliver projects
- ship real apps (auth, APIs, deploy)
- earn side income without another course rabbit hole

**One-liner:**  
Practical guides for MERN developers who want freelance income and shipped projects.

### Why this niche

- Matches your real skills
- Easy to write from experience
- Good for affiliates (hosting, tools, courses)
- Good for your own products later (boilerplates, templates)
- Narrower than “make money online” or “digital marketing”

### Stick to these content pillars

| Pillar | What to write | Share of posts |
|--------|----------------|----------------|
| Freelancing | Pricing, proposals, clients, Upwork, contracts | ~30% |
| Build & ship | MERN/Next tutorials that end in a working app | ~35% |
| Tools | Hosting, DB, auth, deploy comparisons | ~20% |
| Case studies | Real (or anonymized) project stories | ~15% |

### Don’t write (for now)

- Generic “what is React/MongoDB”
- Thin AI-rewritten posts with no code
- Random marketing/crypto posts that don’t fit the niche
- Site redesigns instead of publishing

### Alternatives (only if you hate freelancing content)

1. Build & sell small SaaS with MERN/Next  
2. Practical Next.js production tutorials  
3. AI tools for developers  

Pick **one** niche for at least 6 months.

2. Short, easy to say
3. No hyphens/numbers
4. **One** live domain only
5. Point DNS to Vercel
6. Update `BASE_URL`, sitemap, footer, OG tags
7. 301 redirect old URLs to the new domain

## 4. What “good content” means here

Every post should help the reader do one of these:

1. Get or handle a client better  
2. Ship a feature/app  
3. Choose a tool with confidence  

### Post formats that work

- How-to tutorials (with GitHub repo when possible)
- Tool comparisons (“X vs Y for freelancers”)
- Templates (proposal, estimate, delivery README)
- Checklists (launch, security, handoff)
- Case studies (problem → stack → result → lessons)

### Quality checklist (use before every publish)

- [ ] Clear target reader in the intro
- [ ] Outcome stated early (“by the end you’ll…”)
- [ ] Proper headings (H1 once, then H2/H3)
- [ ] Real code or real process (not fluff)
- [ ] Author bio / experience signal
- [ ] Featured image + alt text
- [ ] Meta title + meta description
- [ ] Keyword-friendly slug
- [ ] 2–3 internal links to related posts
- [ ] One main CTA at the end (email or next step)
- [ ] Proof when possible (screenshot, repo, sample proposal)

Aim for **1,500–2,500+ words** on money/competitive topics. Shorter is OK for focused checklists if they’re dense and useful.

## 6. Publishing system (follow this every time)

### Cadence

- **2 solid posts per week**, or  
- **1 deep post + 1 shorter post** if time is tight  

Consistency beats binge weeks.

### Weekly time budget (side project)

| Work | Hours |
|------|------:|
| Write / edit | 4–6 |
| Topics / outlines | 1 |
| Share / promote | 1–2 |
| Small site fixes | 0–1 |
| **Total** | **~6–9** |

### Batching (recommended weekend flow)

1. Outline 4 posts  
2. Write 2 drafts  
3. Add images/code/repos  
4. Edit with the quality checklist  
5. Publish or schedule in Contentful  
6. Promote the same day  

### Contentful publish steps

1. Write/draft content  
2. Set title, slug, excerpt, cover, category, tags, author, keywords  
3. Preview  
4. Publish  
5. Check the live URL  
6. Confirm it appears after rebuild/ISR  
7. Promote  

### Topic clusters (important for SEO)

Don’t publish random posts forever. Group them.

Example cluster — **Freelance pricing**

- Pillar: complete pricing guide  
- Supports: hourly vs fixed, change requests, contracts, platform vs direct clients  

Example cluster — **Deploy MERN**

- Pillar: production deploy checklist  
- Supports: Railway guide, env vars, Atlas, domains, monitoring  

Publish supporting posts first, then the big pillar, and link them together.

## 7. After you hit publish — distribution

Same day, every post:

1. LinkedIn post (best channel for freelance audience)
2. Optional: Dev.to / Hashnode with **canonical URL** pointing to your site
3. Email your list (once it exists)
4. Only share in communities if it’s allowed and actually helpful

Don’t spam Reddit/Discord. One thoughtful post beats ten links.
